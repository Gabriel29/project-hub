# Backend audit and refactor ledger

Reviewed against the current working tree, including the user's pre-existing SQL-baseline and stage/activity changes. This is a file-by-file logic/architecture review, not a claim that every possible security defect can be excluded. Existing uncommitted removals of EF migrations and retired workflows were preserved, not re-created or attributed to this refactor.

## Findings and disposition

| Severity | Finding | Disposition |
| --- | --- | --- |
| High | Forwarded headers trusted arbitrary proxies and link URLs used request Host | Configured trusted addresses/networks, explicit hosts, validated public origin and full-origin checks |
| High | Object deletion failures were silently abandoned | Transactional deletion jobs, timeout/backoff, multi-worker row claiming and backlog logs |
| Medium | Profile/account changes and stamp invalidation could commit separately | Shared account lock and atomic transaction, cookie refresh after commit |
| Medium | Upload compensation could delete committed bytes after an ambiguous commit error | Independent committed-state check; durable compensation job before immediate cleanup |
| Medium | Generic list reads and per-account DTO queries overfetched data | Direct EF directory/summary/search projections, constant-count account reads and targeted contacts |
| Medium | Missing/null values and null array elements could reach unsafe code | API/application guards and null-safe rules; consistent Problem Details |
| Medium | Project mutations loaded tracked state before acquiring locks | Project lock before state reads; stage/activity/file workflows serialize consistently |
| Low | Large mixed services, multi-record files and inline EF mappings obscured responsibilities | Feature services, mapper, split contracts, per-entity configurations and split integration tests |
| Low | HTTP errors mixed ad-hoc messages with validation bodies | Explicit business error codes independent of message wording, trace IDs and Problem Details across application/HTTP failures; frontend compatibility fallback |
| Low | Backend formatting and docs drifted from current behavior | Root standards, built-in analyzers/CI checks and corrected API/architecture/operations guidance |
| Low | Browser check expected 16px activity body text despite the existing 15px design token | Corrected stale assertion only; production typography unchanged |

## Review boundaries and invariants

- WebAPI calls Infrastructure feature workflows, which use EF directly; Application retains contracts/pure rules and Domain retains entities. Identity operations use one scoped adapter/context split across session, account and access-link files.
- Owner/Admin manage all projects; Clients read their assigned projects/shared or published content. Owner alone manages administrators; Owner/Admin share private project notes and maintenance dates. Application guards supplement controller policies.
- Existing successful routes/JSON remain. Error responses add the deliberate Problem Details/code contract; frontend transport accepts both contracts during rollout.
- The user explicitly authorized a fresh-baseline replacement on October 17, 2026: StorageDeletions is included in 0002, and the standalone cleanup migration is removed. Subsequent schema changes append from 0003. Current baseline SHA-256 checksums are `1d4fb5dce0c02e14814b227b7b2306eff62bb5b9fc2ec889d65d36ee12b6368c` (0001) and `2d4843813d6f1145934cdc262de5d1d11f0225335681e59bfb99473e97278b4b` (0002).
- No production deployment, database reset or storage reset is part of this work. Test factories only drop databases they created. General crash-orphan reconciliation remains future work; bounded signature/package checks do not replace malware scanning.

## EF simplification follow-up

Feature workflows now use `PortalDb` directly. Custom query/repository ports,
repository adapters, unit-of-work and transaction wrappers, and the deletion-queue
wrapper have been removed. See [the architecture boundaries](architecture.md#backend-contracts-and-persistence-boundaries).

- [Workflows](../src/ProjectHub.Infrastructure/Services) execute EF queries and own saves/transactions, with existing permission guards and response projections.
- [PostgresQueries](../src/ProjectHub.Infrastructure/Persistence/PostgresQueries.cs) shares only recursive folder SQL and PostgreSQL locks.
- Identity and business workflows share one scoped context; deletion jobs join the metadata transaction directly.
- [Persistence regression coverage](../tests/ProjectHub.Tests/PortalFlowTests.PersistenceBoundaries.cs) preserves cross-entity and Identity/business rollback checks.
- DTOs and requests remain separated and formatted; no schema or HTTP contract changes are required.
- Validation: all 88 backend tests passed against disposable local PostgreSQL databases, including actual read-workflow tracking and Identity/business rollback coverage. .NET whitespace verification and `git diff --check` passed. Frontend source was unchanged by this simplification.
